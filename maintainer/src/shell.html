The reusable workflow
Version 4.0: installs one agent. Type “Create PBI” in Copilot (or use the New PBI tab here) for a guided, step-by-step intake; business questions come one at a time with selectable answers (VS Code) or numbered options, and can also be answered on the Continue tab. For each business rule it records who enforces it, whether that enforcement is active and whether CDMS and DAB/OCP/GraphQL requests reach it, with evidence for each claim. It asks for PO/BA, technical and final user approval in one summary before creating REFINED-PBI.md; each approval is bound to a fingerprint of what was reviewed, so any later change needs renewed approval. Upgrading retires the earlier version 2 agents (original and Concise) if you never edited them.
  1. First use: choose the actual repository root, review setup and install. Repeat for each different repository, using this same wizard.
  2. Open the application: open the solution in Visual Studio or the repository folder in VS Code, then select the project-specific PBI Builder in Copilot Chat.
  3. Check once: use the setup check prompt below and verify the agent actually reads the configured sources.
  4. New requirement: use the New PBI form or simply type “New PBI” in Copilot.
  5. Refinement: answer one business question at a time and review the saved output documents.
  6. Return later: use Continue PBI, or type “Continue PBI” with the number or folder in a new Copilot chat.
Setup check prompt
Check this PBI Builder setup. Read playbook/pbi-builder/config.json and playbook/pbi-builder/sources.yaml. Read the available reference documents and one relevant application source file. Give the document titles and source file path as evidence. Report missing sources and disabled tools. Do not change any files.
If the agent is missing
  • Confirm the agent is at .github/agents/akzo-sdd-pbi-builder.agent.md in the repository you opened.
  • Reopen the solution/editor and check the agent picker for the exact project-specific name.
  • For Visual Studio, custom agents require 2026 version 18.4 or later. Verify Copilot sign-in and entitlement.
  • Check the Tools panel: enable the configured read/search/edit tools if they are available but disabled.
  • If an older PBI agent is also listed, select the new name with your project. Older definitions are preserved.
Compare with an earlier version
Use Compare old & new to add a pinned v2.0 Original or v2.1 Concise agent for one trial, then Remove comparison agents. Existing user-edited agent files remain protected; a conflict must be reviewed rather than overwritten.
Installation and updates
Existing application instructions, solution files and code are preserved. Setup compares every target file. An unchanged rerun skips matching files. A wizard-managed file can be updated with a backup only if its current contents still match the previous installation record. User-edited files are reported as conflicts.
Use the same repository folder next time. The browser asks for folder access each session; it cannot infer the machine's full path. Optional external source paths are verified by Copilot, not by the browser. Do not edit these setup files concurrently while installation is in progress.
ZIP fallback
Enter your project settings and download the setup ZIP. Extract it and copy its contents into the repository root, including .github. Compare existing files; do not blindly replace them. You can load the extracted config.json above to generate new-PBI or refinement ZIPs. Extract those into the same repository before sending the prompt.
What still needs a person?
Browser folder access, IDE sign-in, agent selection, sending the prompt, business decisions and approvals. The form does not call an AI service or publish Azure DevOps items. “Development-Ready” requires every readiness check to pass and recorded PO/BA, technical and final user approval. Check PBI readiness verifies completeness and consistency, not correctness or who approved.
